## Boundaries and controls

The [approved local roadmap](../03-planning/local-roadmap.md) uses synthetic records, isolated PostgreSQL test targets, local HTTPS, private filesystem storage and real ClamAV. The same typed-parent authorization/permit/quarantine contracts apply; the local file adapter exposes no public path. Cloud service locations and real-data policy validation below are future-use requirements, not local provisioning tasks. Every backend tool executes in backend/.venv.

The browser keeps only a protected session cookie on the provided Vercel origin. Its token is opaque, random, hashed in the database, revocable, and valid for at most seven days. Use `HttpOnly`, `Secure`, `SameSite=Lax`, rotation at authentication, CSRF protection on writes, and `Cache-Control: no-store` for all private responses. The Vercel facade and DigitalOcean API secrets stay server-side and can rotate. The proxy never forwards a browser-computed role. Direct FastAPI staff routes reject requests outside the facade, except transfers using permits. Rate-limit requests and sign-in attempts; logs omit passwords, cookies, and tokens.

Passwords have at least twelve characters, permit passphrases, and are hashed with Argon2id. The intended first administrator runs a one-time script on the deployed server after migrations, chooses their own final password via a hidden TTY prompt, and creates the first account in an audited transaction. The script refuses any existing user or completed bootstrap and has no public route; no password enters shell arguments, environment, files, output, or logs. Later administrators create staff accounts with server-generated one-time temporary passwords. The proposed Q-04 policy leaves accounts `pending_handoff` until verified **in-person** delivery is confirmed, requires a password change before CRM access, and expires temporary credentials after 24 hours; no SMTP, email, SMS, or chat carries them. Before resetting another person's password, the administrator provides their own current password; the target's sessions are revoked and a new temporary credential follows the same handoff. Disabling an account or changing its role revokes affected sessions and prevents unconsumed permits from working. Disabled users remain credited for historical actions. See the [bootstrap runbook](../06-delivery-and-operations/admin-bootstrap.md).

FastAPI makes access decisions against current database state. `administrator` has `manager` rights plus account administration and is the only role that changes agency working days/hours, lunch breaks, or company-car capacity. `manager` can view and edit all business CRM work. `agent` works on contact records where they are primary agent or collaborator; all agents can read developments, blocks, floors, types, physical units/standalone properties, offerings, and shared inventory attachments. Only managers/administrators directly change any inventory hierarchy, facts, prices, stock, or attachments. An authorized deal transition may trigger a domain-controlled stock effect; it never grants unrestricted inventory `PATCH` rights. Commissions, receipts, bulk import, and bulk export remain manager/administrator actions. Search, KPI totals, notifications, autocomplete, and files follow the same scope. An agent dashboard is limited to assigned/collaborative work even though Projects inventory is separately shared. Colleagues see only free/busy intervals; calendar capacity responses disclose no private visit metadata.

If an agent enters a phone already held by a private contact, the response contains only the primary agent's name. This limited disclosure is an explicit functional exception. It contains no contact ID/name, deal count, or document. Even that exception is hidden from the public form. Developers and owners linked to shared development/unit records do not expose contact IDs, names, phones, notes, or private documents in inventory responses unless the caller separately has contact scope. A project briefing is shared inventory text and must never contain private owner/developer contact facts or documents; only safe marketing display may be shown. Private evidence attaches to the protected `contact` record; a `development` or `property` attachment is readable by all agents. Search, project rollups, type counts, and file lists must use the same safe projection, not join private contact data into shared results. A user's configurable list columns are presentation preferences, not permission grants.

## Documents and API

Use private Spaces buckets in Frankfurt, encryption in transit and at rest according to the chosen service, least-privilege access keys, and key rotation. Every object has a typed parent, actor, size, hash, and antivirus verdict. A direct FastAPI upload is limited to 20 MB and an allowlist of formats; quarantine lasts until `clean`. Thumbnails or previews may not bypass that verdict. A short, single-use transfer permit is bound to session, document, action, size, and parent; current permissions are rechecked on use. No public Spaces link, URL token, persistent browser token storage, or OCR. Downloads are logged. A copied link fails without a valid permit. See [file architecture](architecture.md).

Validate inputs, encode outputs, parameterize SQL, prevent XSS/CSRF/IDOR, limit request bodies, and check dependencies and secrets in CI. The website connector authenticates with a server secret, replay protection, and rate limits; its payload cannot choose a staff role or owner. CSV exports neutralize spreadsheet formulas at the start of cells while preserving phones as text.

## Purpose and retention

The proposed policy separates four data sets. KAY must approve it for actual use under the purpose and appropriate-retention principles described by the [CNDP](https://www.cndp.ma/conditions/).

| Data set | Design rule | Required validation |
|---|---|---|
| Contacts and CRM work | No automatic expiry; reversible archiving and reduced access to inactive records. | Define purpose, archive criteria, and any applicable deletion/restriction procedure. |
| Transactions, commissions, evidence | Protect history and originals; automatic purge disabled. | KAY confirms the period and business/legal basis before scheduling any purge. |
| Security audit | Retain 24 months with limited access, timestamps, and integrity, then expire. | Confirm this period fits the actual purpose and obligations. |
| Raw CSV files, quarantine, sessions, permits | Propose short cleanup after processing/expiry, while retaining batch results and necessary evidence under a separate policy. | Set operating periods and verify restore/deletion behavior. |

The proposed locations are Vercel for the facade and DigitalOcean Frankfurt for API, PostgreSQL, and Spaces. Services, backups, logs, and support access may involve other locations. Before using real data, map these flows, processor contracts, access rights, notices to data subjects, and any applicable [international transfer formalities](https://www.cndp.ma/transfert-de-donnees-a-letranger/). This is a release condition, not a claim that compliance is complete. Development and test environments use synthetic data. An access incident requires revocation, evidence preservation, analysis, and a notification decision based on verified obligations.
