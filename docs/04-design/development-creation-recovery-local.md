## Strict original operation and truthful completion

The owner admits only the existing strict development-fields body and fixed
development POST. Copied IDs, counters, capability flags, actor or assignment
fields are rejected before dispatch. Parsed original fields, optional phase,
promoter intent, key and awaited completion callback remain frozen after an
unknown outcome. Field, promoter-choice/removal, stepper, Previous and Cancel
handlers are protected synchronously. Cancel has an accessible disabled state
and leaves the tab order. The existing draft guard protects dirty navigation.

A receipt must be the development branch, have no offering, initial counter1 and
required event. Current identity and a strict current programme matching its ID
and at least its counter precede navigation to that exact programme. Later
current versions remain valid historical completion. Foreign current projections
cannot complete a saved operation. Invalid receipts recover the original key;
acknowledged current-read or awaited UI failures retry completion without POST.
The completed form cannot create again. Known noncommitted validation/reference
errors permit an explicit corrected body with a fresh key.

Phase capability is reviewed and pinned as before: supported unknown phase stays
explicit null, legacy phase remains omitted. Metadata refresh cannot replace an
unknown body. Source unavailability blocks new writes while original recovery
remains. Capability/picker/current authentication denial masks private input;
after acknowledgement it retains only a generic saved fact. Scope replacement
or disposal aborts requests and prevents late state/navigation.

Normalized dirty comparison excludes picker visibility/search and private names;
choosing a promoter sends its ID without filling the shared label. Verified
completion clears the draft. No browser storage, new receipt retention, endpoint,
grant, stock effect or default record is introduced.
