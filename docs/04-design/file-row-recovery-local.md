## One command across polling and completion

`use-file-row-actions.ts` owns original archive/retry-scan body, counter, key,
actor/role, document and awaited completion callback. Unknown replies retain that
operation, including a later409; a newer list version cannot rebase it. Known
receipts retry fresh proof/read/handoff only. Definite conflicts retain the
reviewed archive counter; the current list must be refreshed and confirmation
opened again. Exception detail is not adopted as a new reviewed version.

Collection rows now key by document identity rather than optimistic version.
Transient same-page loading/read failure retains authenticated rows, with new
actions disabled until readable. Pending/recovering rows survive their removal
from the current server page, so an interrupted archive can recover its own
receipt. Same-page updates may refresh their display without replacing the
original operation. Current denial masks rows and clears retained client context.
Upload entry is blocked while a row command is protected; unrelated row commands
still have their own identities.

Pending writes and recovery markers participate in the existing navigation
guard. Paging cannot silently discard a pending command; explicit guarded leave
may abandon uncertain local recovery without rolling back backend history.
Archive confirmation stays mounted until current completion succeeds. A known
receipt followed by denied scope reports only a generic recorded notice.

A background analysis result can retire an old FILE_SCAN_IN_PROGRESS message
without inventing a document version increment. Retry success does not promise
that AV has finished. Current worker metadata supplies the actual state.

## Cancellable private delivery

Downloads/previews have separate disposable lifetimes. The existing permit helper
checks the bound actual page actor/role before requesting a grant. The row pins
the exact selected clean version and checks the permit's document counter/version.
Signals reach grant/bytes/current reads. Read failure, identity change, known
archive, missing clean version, replaced owner or disposal stops late handoff.

Received blobs must match current declared MIME/size. Fresh matching identity and
protected document reads precede URL creation; another live check precedes
display/click. A preview is revoked on close, lost readability or disposal.
Already handed-off downloads retain their existing bounded one-second URL
cleanup. Read-only files still download; write availability is not a read grant.
No public storage/URL, copied permit/proof or client-fabricated permission is added.
