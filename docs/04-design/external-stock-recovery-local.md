## Selected home and original scope

The existing icon action in the selected project/property offering row still
opens its separate external-result confirmation. Current effect facts, date and
shared non-private explanation remain; no tabs, page layout, money field, KAY win,
commission or collection is added. Holiday campaigns do not enter this action.
Exact selected glyphs, tokens, compact phone cards and motion remain unchanged.

Previously the generic inventory command could replace an unknown fingerprint,
repeat an acknowledged write after callback failure, accept a foreign result and
leave the action dependent on an unowned refresh. The dedicated owner now pins
property/development, physical target, offering, original actor/role, strict body,
versions/fingerprint, key and awaited UI completion. The route forwards its
authenticated account and keys the record lifetime to account/role/target; the
dialog also keys its opening offering scope. A replaced scope aborts late work.

Current unrestricted identity must match that origin and be manager or
administrator before inspection, dispatch, original-request retry and completion.
The record context must match the same root/ID. Source unavailability blocks new
saves while leaving original uncertain recovery available. No browser storage.

## Review and result proof

The current target must match the requested ID and minimum known version. The
selected offering must belong to that exact property or development, be current,
retain its kind and target, and match the target version. Stock review is bracketed
by the same target/version/selected-offering reads. Reviewed offering, target and
development versions agree; effect count and unique bounded identities must be
coherent. Foreign, stale or changing data cannot authorize a new save. A replaced,
retired, archived or completed current offering ends read-only without retargeting.

Unknown request input, date, offering, versions and key cannot be replaced.
Return, Escape, refresh and stale input handlers are protected synchronously.
Retry uses only the original command. A receipt must have the exact target kind/
ID and offering ID, a newer target version and its required event ID. Invalid
receipts retrieve only the original request/key. After acknowledgement, current
identity and a scoped target read at least as new as the receipt/known version
precede awaited UI completion and verified host acceptance. A later retired
offering does not erase an acknowledged historical event. Read or parent callback
failure retries completion without another POST.

Known conflicts retain date/explanation and require explicit current effects
review. Stale handlers cannot bypass that requirement. An unchanged completed
action cannot rearm; another operation needs a new explicit current review.
Facade record, stock-review and external-mutation responses also bind their
requested parent/offering identities before returning a private projection.

## Retained record host

Property/programme views retain their last authorized record through transient
source failure and freeze its displayed offering while an operation owns record
busy state, including unknown outcomes. Background responses cannot remove the
opening action. The verified completion installs a monotonic parsed current record
directly. Older/foreign results cannot replace it; current source or command
authority denial still removes private content and retains only a generic saved
fact when acknowledged. Busy ownership releases on success, denial and disposal.
The existing root refresh remains supplementary rather than a completion proof.

Other users of the older `useInventoryCommand` are not claimed recovered by this
slice: development creation/edit, hierarchy, offering/availability, owners and the
property listing wizard still require their own request/host reconciliation.
