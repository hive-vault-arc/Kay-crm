# Client listing links

KAY staff can open **Partager** on a standalone property, a programme unit or a whole programme. A manager or administrator prepares and previews a separate French client listing, then explicitly approves it. Creating an inventory record never publishes it. Staff who can read active inventory can issue a client link to an approved listing. Links expire 30 days after creation. The issuer can revoke their own link; managers and administrators can revoke any link or withdraw the listing. The client signs in to nothing and cannot navigate to other inventory.

The public listing allows a title, optional description, city/neighbourhood and explicit MAD price/period, and reads the category and, for properties, area and room count from the target. It includes only the selected, clean inventory photos (up to 24 in a client listing; the private gallery remains unlimited). Inventory references, exact addresses, coordinates and map links, ownership, contacts, reservations, private descriptions, original photo names and file IDs are not copied. Managers must check the public text and image content for incidental private information before approving. Public images are decoded and re-encoded without embedded location metadata.

The link is a bearer capability: recipients can forward it. The browser reads the fragment on the generic `/partage` page and sends the token only in an HTTPS `X-Kay-Listing-Link` header to the configured API origin. PostgreSQL stores only a SHA-256 digest; an idempotent staff retry can reconstruct the same capability using the backend secret. Link values do not appear in list responses, audit events, paths or queries. The public API requires the exact frontend origin and denies missing, expired, revoked or stale links uniformly. That browser boundary does not replace token authorization. It never accepts CRM sessions as a substitute. The page is excluded from indexing and neither client data nor media is cached. Already viewed or saved material cannot be recalled.

Changes to a target (or the parent programme of a unit) invalidate its snapshot and require review. New approvals that change the snapshot invalidate old links. A photo archived or unavailable after approval is no longer served. Inventory photos stay in private storage; each read checks the grant again after fetching and sanitizing the media. Recovery revokes links restored from backups.

Roll out backend and migration `0040_inventory_shares` before enabling `INVENTORY_SHARES_ENABLED=true`. Keep the flag off until the intended production frontend origin, private object storage and release checks have been verified. Turning the flag off disables public reads and staff management immediately.
