## One original operation and lifetime

The uploader holds its validated original metadata, immutable File selection,
key, known document/version and actor context. After an unknown metadata reply,
the picker and alternate upload entry actions cannot replace that operation.
Retry uses the same metadata/key/file; acknowledged metadata goes through a
current protected read instead of another metadata create. Managed-draft and
recovery markers prevent metadata preparation from accepting the full upload.

Metadata dispatch, protected reads, permit issuance and bytes receive the owned
abort signal. Active parent/current writability and component lifetime are
checked between asynchronous stages; late progress, transfer and private state
updates are refused after disposal. Current list denial/writability withdrawal
closes and clears private selection; definite operation denial masks the panel.
Reopening its ordinary drawer remounts its normal authorized read boundary.

Actual page actor/role keys the uploader at each of its5 production call sites.
Metadata/current-read proof and a new optional guard inside `requestFilePermit`
check original actor/role/password context before the grant request. Inventory
attachments retain the existing M/A restriction. The optional guard leaves other
permit callers' behavior unchanged; backend scope and publication are decisive.

Receipts/reads must match original file metadata, active attachment purpose,
canonical document ID and known minimum counter. A fresh grant must report the
next document counter and a valid version ID. On byte-response interruption, a
current read of that exact issued version can recognize published pending/clean/
rejected state and complete without another grant or byte send. An unuploaded
version follows the existing fresh-grant/new-version rule; missing/foreign/stale
projection does not silently retarget. This does not prove exactly-once versions
across actual concurrent publication races, which remain native/SQL work.

Known publication completion says to consult analysis in the list; it never
fabricates a clean verdict. Explicit guarded discard releases the local original
operation before another file may be chosen. It does not delete or roll back a
server metadata reservation or execute retention.
